# Mock Data Generator

A comprehensive mock data generation system for the AI Content Monetization platform. This tool creates realistic test data for all DynamoDB tables with proper referential integrity, IAB taxonomy integration, and realistic usage patterns.

## 🎯 Overview

The Mock Data Generator creates production-quality test data for:

- **Content Records**: Articles, reports, videos, images, and documents with IAB taxonomy
- **Partner Records**: API partners with authentication keys and usage quotas  
- **Job Records**: Processing jobs with realistic timing and status distributions
- **Access Logs**: API usage logs with realistic traffic patterns and billing data

## 🚀 Quick Start

### Generate Default Mock Data
```bash
# Generate default amounts (50 content, 10 partners, 1000 logs, 100 jobs)
make generate-mock-data

# Or run directly
python generate_mock_data.py
```

### Clear and Regenerate Fresh Data
```bash
# Clear existing data and generate fresh data
make generate-mock-data-clean

# Or run directly
python generate_mock_data.py --clear-existing
```

### Generate Custom Amounts
```bash
# Generate custom amounts via Makefile
make generate-mock-data-custom CONTENT_COUNT=100 PARTNER_COUNT=20 CLEAR_EXISTING=true

# Or run directly with custom parameters
python generate_mock_data.py --content-count 100 --partner-count 20 --access-log-count 2000 --clear-existing
```

## 📊 Generated Data Structure

### Content Records (`cm-content`)
- **Content Types**: article, report, video, image, document
- **IAB Categories**: Loaded from `assets/iab-content-taxonomy.tsv`
- **Realistic Data**: Titles, descriptions, authors, publishers using Faker
- **Metadata**: Word counts, quality scores, engagement metrics

### Partner Records (the `PartnerTableName` stack output)
- **Partner Types**: publisher, ai_operator, analytics_provider
- **Shape**: `PARTNER#<id>` / `META` records with operation-id permissions and no keys.
  Keys are API Gateway keys issued by `deployment/data/add-sample-partners.py`.
- **Table name**: generated by CloudFormation. The CLI reads it from `--partner-table-name`,
  `PARTNER_TABLE_NAME`, or the `PartnerTableName` output of `--stack-name`
  (default `ContentMonetizationStack`). `--clear-existing` never clears this table: its
  `KEY#` items track live gateway keys, so partner records are upserted instead.
- **Business Data**: Company information, contact details, billing info

### Job Records (`cm-jobs`)
- **Job Types**: embedding, processing, analysis
- **Status Distribution**: 70% completed, 15% pending, 10% failed, 5% processing
- **Timing**: Realistic creation, start, and completion timestamps
- **Parameters**: Job-specific input parameters and output data

### Access Logs (`iab-access-logs`)
- **Usage Patterns**: Realistic traffic distribution across time
- **Endpoints**: `/api/v1/query`, `/api/v1/content`, etc.
- **Response Codes**: Weighted distribution (80% success, 20% errors)
- **Billing**: Calculated billing units based on response codes

## 🔗 Referential Integrity

The generator ensures proper relationships between tables:

- **Jobs** reference existing content and partner IDs
- **Access Logs** reference existing partner IDs and optionally content IDs
- **Validation** checks all foreign key relationships
- **Orphan Detection** identifies unreferenced records

## 🔧 Advanced Usage

### Programmatic Usage
```python
from mock_data_generator.config import GeneratorConfig
from mock_data_generator.generator import MockDataGenerator

# Create configuration
config = GeneratorConfig(content_count=100, partner_count=20, clear_existing=True, aws_profile="genai")

# Generate data
generator = MockDataGenerator(config)
success = generator.validate_aws_connectivity()

if success:
    # Generate all data types
    content_data = generator.generate_content_data()
    partner_data = generator.generate_partner_data()

    # Write to DynamoDB
    generator.batch_write_items_chunked("cm-content", content_data)
    generator.batch_write_items_chunked(generator.TABLE_NAMES["partners"], partner_data)
```

### Custom IAB Taxonomy
The generator loads IAB categories from `assets/iab-content-taxonomy.tsv`. To use custom categories:

1. Update the TSV file with your categories
2. Follow the existing format: Tier 1, Tier 2, Tier 3, Tier 4 columns
3. The generator will automatically map categories to content types

## 🚨 Important Notes

### Data Safety
- **⚠️ Clear Operations**: `--clear-existing` will delete ALL data in target tables
- **Confirmation Required**: Interactive confirmation for destructive operations
- **Backup Recommended**: Always backup production data before clearing

### AWS Requirements
- **Credentials**: Valid AWS credentials for the specified profile
- **Permissions**: DynamoDB read/write access to target tables
- **Tables**: Target DynamoDB tables must exist and be active

### Performance Considerations
- **Batch Operations**: Uses DynamoDB batch operations (25 items per batch)
- **Rate Limiting**: Includes delays between batches to avoid throttling
- **Memory Usage**: Generates data in memory before writing (suitable for test volumes)

## Deploy_Path Seed_Step (`make seed-data`)

The CI Deploy_Path runs a **Seed_Step** after `make migrate-taxonomy` (wired into `make
deploy-backend`) that populates every `cm-*` table the Integration_Tier depends on:

1. `generate_mock_data.py` — content, partners, jobs, access-logs, analytics, pricing-rules,
   pricing-transactions.
2. `deployment/data/add-sample-partners.py` — sample partners with known API keys.
3. `seed_bot_rules_and_licenses.py` — `cm-bot-rules` via the generator's `generate_bot_rules_data()`
   path (no live WAF WebACL required), plus deterministic sample `cm-licenses` documents (one carries
   the optional `pricing` field with CoMP-style `pricetype` tiers).

Run it directly:

```bash
AWS_PROFILE=genai make seed-data                 # seed without clearing (adds to existing data)
AWS_PROFILE=genai CLEAR_EXISTING=true make seed-data   # clear generator-owned tables, then seed
```

### Idempotency / `CLEAR_EXISTING`

- License documents use **deterministic** `license_id` + `version` keys, so re-running upserts in
  place (never duplicates), regardless of `CLEAR_EXISTING`.
- The generator-owned tables (content/partners/jobs/analytics/access-logs/pricing/bot-rules) use
  random ids, so seeding **without** clearing accumulates rows. To keep a re-seeded environment in a
  consistent, non-duplicated state, pass `CLEAR_EXISTING=true` (the Deploy_Path does this
  automatically) — it clears those tables via `clear_all_tables()` before re-seeding.
